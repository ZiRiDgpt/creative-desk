# Creative Desk

Рабочий прототип для постановки, согласования и учёта задач креативного отдела.

## Запуск

Нужен Node.js 22.13 или новее. Сторонних зависимостей нет.

```sh
npm start
```

В Windows PowerShell также можно использовать `npm.cmd start`.

Откройте [локальное демо](http://127.0.0.1:3030/). При первом открытии загрузится аккаунт байера и появятся девять тестовых задач. Все тестовые аккаунты используют одну доску. Переключатель аккаунтов находится в верхней панели.

## Как проверить

1. **Анна Волкова, байер.** Создайте задачу с названием, оффером, GEO, типом, количеством, описанием, приоритетом и дедлайном. При желании добавьте референсы.
2. **Марк Соколов или Лена Ким, креативщик.** Откройте новую задачу и возьмите её в работу. Сдайте результат как ссылку или файл до 1 МБ и внесите расходы по AI-сервисам.
3. **Анна Волкова.** Верните результат на правки и укажите, что исправить. Переключитесь на выбранного исполнителя, сдайте вторую версию с дополнительными расходами и примите её от имени байера.
4. **Денис Орлов, руководитель.** Откройте аналитику. Сверьте количество задач, загрузку, сроки и расходы с карточкой задачи.

## Как считаются показатели

- Время выполнения считается от взятия в работу до финальной приёмки. В него входят проверка и правки. Среднее учитывает принятые задачи.
- Загрузка — число назначенных незавершённых задач, включая проверку и правки.
- Просрочена незавершённая задача с истёкшим дедлайном. Даты в интерфейсе отображаются в часовом поясе браузера.
- Кредиты суммируются по всем сдачам, включая правки. Названия сервисов группируются без учёта регистра. Единицы разных сервисов показываются в отчёте по сервисам, а общий показатель — их арифметическая сумма.

## Реализация

- `public/` — интерфейс на HTML, CSS и JavaScript. Смена статуса происходит через действия в карточке с учётом текущей роли.
- `server/app.mjs` — HTTP API, проверка ролей и переходов, формирование истории и аналитики. Смена статуса использует номер версии задачи для защиты от одновременных изменений.
- `server/local.mjs` — локальный сервер на Node.js. Данные сохраняются в `data/desk.sqlite`. В Sites тот же API работает как Worker с базой D1.
- `drizzle/0000_initial.sql` — схема базы. История и версии хранятся с задачей. Вложения находятся в отдельной таблице и сохраняются в одной транзакции с результатом.
- `npm run build` собирает Worker в `dist/server/index.js`.

Вход без пароля предназначен для проверки сценариев с тестовыми данными. Роли и разрешения проверяет сервер. В демо используется одна общая доска, а для крупных файлов предусмотрена сдача по ссылке.

## Использование AI

Codex помог разобрать требования, определить сценарий демонстрации, написать интерфейс, API и схему базы, а также проверить переходы статусов, ролевые ограничения и агрегацию расходов. Работа велась в одном чате без субагентов.
